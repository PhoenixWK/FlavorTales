Phase 1 – Vendor Tạo POI

POST /api/poi → PoiController.createPoi() → validateBoundary() → checkProximityConflict() → poiRepository.save()

Actors

Vendor Browser JwtAuthenticationFilter PoiController PoiService PoiRepository → MySQL Primary EmailService (@Async)
Geofence validation xảy ra phía SERVER khi tạo POI: (1) validateBoundary() kiểm tra POI nằm trong vùng food-street (config: center lat/lng + max-radius-m). (2) checkProximityConflict() từ chối nếu có POI active nào khác cách ≤ 5m (tránh duplicate). Cả hai dùng Haversine formula với Earth radius = 6,371,000 m.

Phase 2 – Admin Xem Danh Sách Pending

GET /api/shop/admin/pending → ShopController.getPendingShops() → ShopService → JdbcTemplate

Kiến trúc quan trọng: Admin duyệt POI KHÔNG qua PoiController. Endpoint approval nằm trong ShopController vì POI và Shop được submit cùng nhau. Khi approve shop → ShopService tự động set cả shop.status = active VÀ poi.status = active.
sequenceDiagram autonumber participant AB as Admin Browser participant JWT as JwtAuthentication
Filter participant ShC as ShopController
/api/shop/admin participant ShS as ShopService participant JT as JdbcTemplate
MySQL Primary AB->>+JWT: GET /api/shop/admin/pending
Authorization: Bearer {adminToken} JWT->>JWT: Validate JWT, check ROLE_admin JWT-->>-ShC: forward ShC->>+ShS: getPendingShops() ShS->>+JT: SELECT s.*, p.latitude, p.longitude,
p.radius, u.email as vendorEmail,
fa.file_url as avatarUrl
FROM shop s
JOIN poi p ON s.poi_id = p.id
JOIN user u ON s.vendor_id = u.id
LEFT JOIN file_asset fa ON s.avatar_file_id = fa.id
WHERE s.status = 'pending' JT-->>-ShS: List<Map<String, Object>> ShS-->>-ShC: List<AdminShopResponse> {
shopId, name, description,
vendorEmail, latitude, longitude,
radius, avatarUrl, galleryUrls,
createdAt } ShC-->>AB: 200 OK
ApiResponse { data: [...] } Note over AB: Admin xem danh sách,
click vào từng shop để review chi tiết

Phase 3A – Admin Phê Duyệt (Approve)

PATCH /api/shop/admin/{shopId}/approve → ShopService.approveShop() → UPDATE shop + poi → @Async email

sequenceDiagram autonumber participant AB as Admin Browser participant ShC as ShopController
/api/shop/admin participant ShS as ShopService
[@Transactional] participant JT as JdbcTemplate
MySQL Primary participant ES as EmailService
[@Async] participant VE as Vendor Email
(SMTP) AB->>+ShC: PATCH /api/shop/admin/{shopId}/approve
Authorization: Bearer {adminToken}
Body: { "notes": "Approved, looks great!" } Note over ShC: Extract notes from request body
Extract adminEmail from Authentication ShC->>+ShS: approveShop(shopId, notes) Note over ShS: @Transactional – atomic ShS->>+JT: SELECT shop_id, poi_id, vendor_id,

WHERE id = ? JT-->>-ShS: rows affected = 1 ShS->>+JT: UPDATE poi
SET status = 'active',
updated_at = NOW()
WHERE id = ? (shop.poi_id) JT-->>-ShS: rows affected = 1 Note over ShS,JT: Transaction commits here ShS->>+ES: sendShopApprovedEmail(
vendorEmail, shopName, notes) Note over ES: @Async – separate thread pool
Không block response về admin ES->>+VE: SMTP sendMimeMessage(
to: vendorEmail,

body: HTML template với shopName, notes ) VE-->>-ES: sent ES-->>-ShS: (async) ShS-->>-ShC: void (success) ShC-->>-AB: 200 OK
ApiResponse { success: true,
message: "Shop approved successfully" }
