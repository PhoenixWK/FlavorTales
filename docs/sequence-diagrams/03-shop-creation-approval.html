Step 1 – Vendor Upload Ảnh Shop lên Cloudflare R2

POST /api/file/upload → FileService.uploadImage() → R2FileStorageService.upload() → S3Client.putObject()

Actors

Vendor Browser JwtAuthenticationFilter FileController /api/file/upload FileService R2FileStorageService AWS S3Client SDK Cloudflare R2 (S3-compatible) MySQL Primary (file_asset table)
Flow này được gọi nhiều lần: Vendor upload avatar (1 lần) + gallery images (tối đa 5 lần) trước khi tạo Shop. Mỗi lần upload trả về fileId, sau đó được dùng trong ShopCreateRequest.avatarFileId và additionalImageIds.
sequenceDiagram autonumber participant VB as Vendor Browser participant JWT as JwtAuthFilter participant FC as FileController participant FS as FileService participant R2S as R2StorageService participant S3 as S3Client SDK participant R2 as Cloudflare R2 participant DB as MySQL Primary VB->>+JWT: POST /api/file/upload
multipart/form-data, Bearer token
file=binary image data JWT->>JWT: Validate JWT, extract vendorEmail JWT-->>-FC: forward FC->>+FS: uploadImage(file, vendorEmail) FS->>FS: Validate MIME: file.getContentType()
must be image/jpeg or image/png alt Invalid MIME type FS-->>FC: throw InvalidFileTypeException FC-->>VB: 400 Bad Request: Only JPEG/PNG allowed end FS->>FS: Validate size: file.getSize()
must be under 5MB (5242880 bytes) alt File too large FS-->>FC: throw FileTooLargeException FC-->>VB: 400 Bad Request: File must be under 5MB end FS->>+R2S: buildImageKey(vendorEmail, originalFilename) Note over R2S: Extract username prefix from email
Result: username/images/filename R2S-->>-FS: objectKey = username/images/filename FS->>FS: bytes = file.getBytes() FS->>+R2S: upload(objectKey, bytes, mimeType) R2S->>R2S: Build PutObjectRequest
bucket=R2_BUCKET, key=objectKey
contentLength, contentType=mimeType R2S->>+S3: s3Client.putObject(request,
RequestBody.fromBytes(bytes)) Note over S3,R2: HTTP PUT to Cloudflare R2
S3-compatible API S3->>+R2: PUT /R2_BUCKET/objectKey R2-->>-S3: 200 OK with ETag S3-->>-R2S: PutObjectResponse R2S->>R2S: publicUrl = R2_PUBLIC_URL/objectKey R2S-->>-FS: publicUrl string FS->>+DB: INSERT INTO file_asset
object_key, file_url, original_filename
mime_type, size_bytes, uploaded_by, created_at DB-->>-FS: generated fileId integer FS-->>-FC: FileUploadResponse
fileId, fileUrl, originalFilename, mimeType, sizeBytes FC-->>VB: 200 OK - fileId and fileUrl returned Note over VB: Store fileId for next step

Step 2 – Vendor Tạo Shop (Dùng fileId Đã Upload)

POST /api/shop → ShopService.createShop() → JdbcTemplate INSERT → @Async email admin

Actors

Vendor Browser JwtAuthenticationFilter ShopController /api/shop ShopService (JdbcTemplate) MySQL Primary EmailService (@Async)
Lưu ý: ShopService dùng JdbcTemplate trực tiếp (không qua JPA Repository) để INSERT shop và shop_image records. Shop được tạo với status = 'pending', liên kết với POI đã tạo trước (cùng vendor).
sequenceDiagram autonumber participant VB as Vendor Browser participant JWT as JwtAuthFilter participant ShC as ShopController participant ShS as ShopService participant JT as JdbcTemplate participant ES as EmailService participant AE as Admin Email VB->>+JWT: POST /api/shop
Bearer vendorJwt
ShopCreateRequest: name, description
avatarFileId=42, additionalImageIds=[43,44] JWT->>JWT: Validate JWT, extract vendorEmail JWT-->>-ShC: forward ShC->>+ShS: createShop(ShopCreateRequest, vendorEmail) ShS->>+JT: SELECT id FROM poi
WHERE vendor_email=? AND status IN pending,active
ORDER BY created_at DESC LIMIT 1 JT-->>-ShS: poiId of linked POI ShS->>+JT: INSERT INTO shop
poi_id, vendor_id, name, description
avatar_file_id, status=pending
opening_hours JSON, tags JSON, created_at=NOW() JT-->>-ShS: generated shopId loop For each additionalImageId ShS->>+JT: INSERT INTO shop_image
shop_id, file_asset_id, display_order JT-->>-ShS: OK end ShS->>+ES: sendAdminNewShopNotification(shopName, vendorEmail) Note over ES: Async - fires in separate thread
does not block response ES->>+AE: SMTP: New shop submission shopName
from vendor vendorEmail AE-->>-ES: sent ES-->>-ShS: async fire-and-forget ShS-->>-ShC: ShopCreateResponse: shopId, status=pending ShC-->>VB: 201 Created - shopId and status=pending

Step 3 – Admin Phê Duyệt Shop (Full @Transactional Flow)

PATCH /api/shop/admin/{shopId}/approve → UPDATE shop + poi + @Async email vendor

sequenceDiagram autonumber participant AB as Admin Browser participant JWT as JwtAuthFilter participant ShC as ShopController participant ShS as ShopService participant JT as JdbcTemplate participant PCS as PoiCacheService participant RD as Redis participant ES as EmailService participant VE as Vendor Email AB->>+JWT: PATCH /api/shop/admin/shopId/approve
Authorization: Bearer adminJwt
Body: notes=All requirements met JWT->>JWT: Validate JWT, verify ROLE_admin JWT-->>-ShC: forward request ShC->>+ShS: approveShop(shopId, notes) ShS->>+JT: SELECT shop.id, shop.poi_id,
shop.name, user.email as vendorEmail
FROM shop JOIN user ON vendor_id
WHERE shop.id = shopId JT-->>-ShS: returns poiId, vendorEmail, shopName Note over ShS,JT: BEGIN TRANSACTION ShS->>+JT: UPDATE shop SET status=active,
approved_at=NOW(), admin_notes=notes
WHERE id=shopId JT-->>-ShS: 1 row updated ShS->>+JT: UPDATE poi SET status=active,
updated_at=NOW()
WHERE id=poiId JT-->>-ShS: 1 row updated Note over ShS,JT: COMMIT TRANSACTION ShS->>+PCS: evict(poiId) PCS->>+RD: DEL poi-poiId RD-->>PCS: deleted PCS->>RD: DEL poi-list-active RD-->>-PCS: deleted PCS-->>-ShS: cache invalidated ShS->>+ES: sendShopApprovedEmail(vendorEmail, shopName, notes) Note over ES: Async - runs in separate thread
fire-and-forget, does not block ES->>+VE: SMTP: subject=Your shop is now live
to=vendorEmail, body=HTML template VE-->>-ES: email sent ES-->>-ShS: async fire-and-forget ShS-->>-ShC: void ShC-->>-AB: 200 OK
ApiResponse: success=true,
