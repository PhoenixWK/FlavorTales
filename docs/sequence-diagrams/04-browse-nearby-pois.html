Main Flow – Fetch Active POIs với Redis Read-Through Cache

GET /api/poi → @ReadOnly → DataSourceAspect → PoiCacheService → Redis / MySQL Replica

Actors

Tourist Browser / Mobile App PoiController /api/poi DataSourceAspect [AOP] PoiService PoiCacheService Redis (poi:list:active, TTL 1h) RoutingDataSource MySQL Replica [Read-Only]
Read Path Architecture: @ReadOnly AOP annotation → DataSourceAspect intercepts → set DataSourceContextHolder = REPLICA → RoutingDataSource.determineCurrentLookupKey() returns replica key → all SQL goes to MySQL Replica. Redis cache key = "poi:list:active", TTL = 3600 seconds (1 hour). Cache failure → silent fallback to DB (Redis errors are caught and logged).

Cache Invalidation – Khi POI/Shop Thay Đổi

PoiCacheService.evict() + evictActivePoisList() → Redis DEL keys

Cache eviction được trigger bởi: PoiService.updatePoi(), PoiService.deletePoi(), PoiService.likePoi(), PoiService.unlikePoi(), và ShopService.approveShop() / ShopService.rejectShop().
sequenceDiagram autonumber participant PS as PoiService /

exception được catch + log,
app tiếp tục chạy bình thường

→ Cache MISS → fetch from DB
→ Re-populate Redis cache
