Diagram 8 · Theo dõi số lượng Tourist theo thời gian thực (WebSocket / STOMP)

1. Geofence Detection 2. POI Approval Workflow 3. Shop Creation & Approval 4. Browse Nearby POIs 5. File Upload to R2 6. Audio TTS & Upload 7. Audio Translation 8. Realtime Tourist Tracking ← Index
Kiến trúc tổng quan: Hệ thống dùng STOMP over SockJS (Spring @EnableWebSocketMessageBroker) để push số lượng tourist đang online theo thời gian thực. Có hai luồng song song:
① Tourist App subscribe /topic/tourist-ping → server ghi nhận presence;
② Admin Dashboard subscribe /topic/active-visitors → nhận count update ngay khi tourist kết nối / mất kết nối.
Ngoài ra, Admin có thể truy vấn thống kê lịch sử qua REST GET /api/analytics/admin/visitors/stats (MongoDB aggregation).

Phase 1 – Tourist App Kết Nối WebSocket & Đăng Ký Presence

SockJS handshake → STOMP CONNECT → SUBSCRIBE /topic/tourist-ping → VisitorPresenceRegistry.add()

Actors

Tourist App (Frontend) SockJS / STOMP Client WebSocketConfig (Spring) VisitorPresenceEventListener VisitorPresenceRegistry ActiveVisitorBroadcaster
Endpoint WebSocket: ws://<host>/ws với SockJS fallback. Server cấu hình trong WebSocketConfig: topic prefix /topic, app prefix /app. Tourist App không cần JWT để kết nối WebSocket – presence tracking là anonymous.

Phase 2 – Admin Dashboard Kết Nối & Nhận Count Realtime

Admin subscribe /topic/active-visitors → nhận push ngay khi count thay đổi

Actors

Admin Dashboard (Frontend) SockJS / STOMP Client WebSocketConfig (Spring Broker) ActiveVisitorBroadcaster VisitorPresenceRegistry
Lưu ý bảo mật: Admin Dashboard phải đính kèm Authorization: Bearer <JWT> trong STOMP CONNECT headers (hoặc HTTP cookie). SecurityConfig bảo vệ endpoint /api/analytics/**, nhưng WebSocket handshake /ws có thể cấu hình thêm AuthChannelInterceptor để xác thực STOMP session.

Phase 3 – Tourist Mất Kết Nối (Tab Đóng / Network Loss)

SessionDisconnectEvent → VisitorPresenceRegistry.remove() → broadcast count mới

Actors

Tourist App (Browser) Spring WebSocket Infra VisitorPresenceEventListener VisitorPresenceRegistry ActiveVisitorBroadcaster Admin Dashboard
Quan trọng: Spring WebSocket phát hiện mất kết nối trong vòng vài mili-giây thông qua TCP close / WebSocket close frame. Không cần heartbeat poll. SessionDisconnectEvent được fire kể cả khi client đóng tab đột ngột (browser gửi TCP FIN).

Phase 4 – Admin Truy Vấn Thống Kê Lịch Sử (REST + MongoDB Aggregation)

GET /api/analytics/admin/visitors/stats?period=day|week|month|year → VisitorStatsService MongoDB $group pipeline

Actors

Admin Dashboard AdminAnalyticsController VisitorStatsService SessionCreatedEventListener MongoDB (visitor_events) TouristSessionService (event source)
Luồng ghi dữ liệu: Khi tourist tạo session mới (POST /api/tourist/sessions), TouristSessionService publish SessionCreatedEvent. SessionCreatedEventListener (analytics module) lắng nghe event và lưu VisitorEvent { timestamp } vào MongoDB collection visitor_events.
Luồng đọc: VisitorStatsService.getStats(period) chạy MongoDB aggregation pipeline $match → $group (dateToString) → $sort để trả về tập List<VisitorStatPoint> cho dashboard vẽ chart.
