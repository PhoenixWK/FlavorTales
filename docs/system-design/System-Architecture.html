1. Tổng quan kiến trúc
Mô hình tổng thể và các nguyên tắc thiết kế

FlavorTales được xây dựng theo mô hình kiến trúc phân tầng (Layered Architecture) kết hợp module hoá (Modular Monolith) ở phía backend. Toàn bộ hệ thống đóng gói bằng Docker Compose, phục vụ ba nhóm người dùng: Vendor, Admin và Khách du lịch ẩn danh.

🧑‍🍳
Vendor (Chủ quán)
Đăng ký tài khoản, tạo POI, quản lý quán ăn, menu, hình ảnh và âm thanh TTS
🛡️
Admin
Phê duyệt POI / Shop, quản lý người dùng, xem analytics và dashboard thời gian thực
🗺️
Khách du lịch ẩn danh
Duyệt bản đồ, nghe audio giới thiệu, tương tác với POI — không cần đăng ký

Nguyên tắc thiết kế chính

🔗 Tách biệt mối quan tâm
Frontend, Backend và Database hoàn toàn độc lập, giao tiếp qua REST API và WebSocket
📦 Module hoá backend
Mỗi nghiệp vụ (auth, POI, shop, audio…) là một Maven module riêng biệt
⚡ Phân tách đọc/ghi
MySQL Master nhận ghi; MySQL Replica xử lý đọc — định tuyến tự động qua AOP
🔑 Stateless Authentication
JWT trong HTTP-only cookie; không lưu phiên phía server
🔄 Xử lý bất đồng bộ
Email, dịch thuật, TTS đều chạy bất đồng bộ — không chặn luồng chính
📡 Thời gian thực
WebSocket STOMP cho tính năng theo dõi khách du lịch trực tuyến
🗺️

🔒 Bảo vệ Route (Middleware)

Next.js Middleware kiểm tra JWT cookie phía server trước khi render trang:

Request → middleware.ts │ ├── /vendor/** → kiểm tra cookie access_token │ └── Thiếu token → redirect /auth/vendor/login?from= │ └── /admin/** → kiểm tra cookie admin_access_token └── Thiếu token → redirect /auth/admin/login?from=

5. Cơ sở dữ liệu
MySQL 8 · Redis 7.2 · MongoDB 7.0

🐬 MySQL 8.0 — Dữ liệu nghiệp vụ chính

🔵
MySQL Primary (Master)
Port 3308 → 3306
Nhận toàn bộ INSERT, UPDATE, DELETE. Nguồn dữ liệu thực tế. GTID replication chủ động sang Replica.
🟡
MySQL Replica (Slave)
Port 3309 → 3306
Chỉ đọc (read_only=ON). Xử lý SELECT queries. GTID Auto-position. Bootstrap tự động qua replica-setup.sh.

8. Bảo mật
JWT, Rate limiting, BCrypt, CORS, File validation
🔑
JWT Authentication
  • Algorithm: HMAC-SHA-256
  • Access token: 24h (7d nếu Remember Me)
  • Refresh token: 30 ngày
  • Lưu trong HTTP-only cookie
  • Blacklist JWT đã đăng xuất (Redis)
  • Vô hiệu sau đổi mật khẩu (passwordChangedAt)
🛡️
Login Protection
  • Rate limit: 5 lần / 15 phút / IP
  • Lockout: 10 lần thất bại → khoá 30 phút
  • Enumeration protection: thông báo chung
  • BCrypt cost factor 12
  • Reset password: tối đa 3 yêu cầu/giờ/IP
🌐
Network Security
  • CORS: cấu hình qua env APP_CORS_ALLOWED_ORIGINS
  • HTTPS bắt buộc (Cloudflare Tunnel)
  • Session policy: STATELESS
  • SecurityConfig: /api/auth/** public
  • Mọi route khác yêu cầu JWT hợp lệ
📁
File Upload Security
  • Chỉ chấp nhận JPEG/PNG
  • Giới hạn 20MB/file, 25MB/request
  • Audio tối đa 10MB
  • Pre-signed URL để upload trực tiếp lên R2
  • Naming convention đảm bảo cô lập theo user
🔍
Privacy
  • Tourist session không lưu PII
  • Chỉ dùng UUID ngẫu nhiên cho tourist
  • HTTP-only cookie ngăn XSS truy cập token
  • Bí mật lưu trong env vars, không hardcode
⚠️
Exception Handling
  • 40+ custom exception types
  • Global @ControllerAdvice maps to HTTP codes
  • Không dùng RuntimeException cho business errors
  • Ví dụ: TooManyLoginAttemptsException, AccountSuspendedException

🌍 Thiết kế đa ngôn ngữ

Mỗi entity có thể dịch được (POI, Shop) có bảng translation riêng theo ngôn ngữ, quan hệ 1:1 với bảng cha:

Bảng chínhBảng dịch (1:1)Nội dung lưu trữ
poipoi_english, poi_korean, poi_chinese, poi_russian, poi_japanesename, address, description, translated_at, status dịch

🔄 Trạng thái nghiệp vụ

👤 user.status

inactive → active → suspended / disabled / rejected

📍 poi.status

pending → active / rejected / inactive / deleted

🏪 shop.status

pending → active / rejected / disabled

🎵 audio.processing_status

processing → completed / failed
📌 Quy tắc nghiệp vụ quan trọng: Phê duyệt/từ chối Shop không tự động thay đổi trạng thái POI. Hai luồng phê duyệt hoàn toàn độc lập. Admin endpoint shop: PATCH /api/shop/admin/{shopId}/approve|reject.
